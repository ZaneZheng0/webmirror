## 2. 执行摘要

WebMirror 主动处理并运行来源网站的 HTML、JavaScript、Worker、WASM、WebGL 模型及其他资源，因此“来源页面”和“本地镜像”必须始终视为不可信代码。产品的核心安全目标不是让镜像内容变得可信，而是把它限制在一个不能读取本机任意文件、不能控制辅助程序、不能访问本机或私有网络、不能泄漏浏览器凭据的隔离环境中。

Beta 版本采用以下严格安全配置：

1. 仅在用户明确点击后处理当前活动标签页。
2. 仅下载公开 `http:` 或 `https:` 静态资源；拒绝本机、私网、链路本地、保留地址及危险协议。
3. “用户有复制授权”不等同于“允许保存登录凭据”。Beta 不持久化会话绑定资源所需的 Cookie、Authorization、浏览器存储或表单值。
4. 来源页面不能直接向 Native Messaging Host 发送消息，也不能向本地辅助程序提供任意命令、路径或下载 URL。
5. 预览面只读，控制面独立；预览中的不可信页面不能调用任务控制、文件、安装、更新或导出接口。
6. 所有 URL、重定向、输出路径、ZIP 条目和协议消息在每个信任边界重新校验。
7. 日志、清单、报告、诊断包和 ZIP 中不得包含 Cookie、Token、密码、用户输入值或未脱敏的签名 URL。
8. 安装包、辅助程序和更新包必须可验证来源、完整性和版本兼容性。

以下事件属于发布阻断：

- 凭据写入磁盘、日志、清单、缓存、报告、ZIP 或诊断包。
- 辅助程序连接到被禁止的本机、私网或保留地址。
- 任意镜像目录外读取或写入。
- 预览页面可以调用控制 API 或操作其他任务。
- 未签名或签名校验失败的辅助程序、安装包或更新包被执行。
- 任意未关闭的 Critical/High 安全风险。

## 3. 范围与非目标

### 3.1 范围内组件

- Chrome/Edge Manifest V3 扩展。
- Popup、结果页、扩展 Service Worker 和 CDP 会话管理。
- Extension 与 Local Helper 之间的 Native Messaging。
- Local Helper 的下载、缓存、路径重写、本地预览、验证、报告和 ZIP 导出。
- Playwright 验证浏览器及其临时用户数据目录。
- Windows 安装、Native Host 注册、升级、回滚和卸载。
- 镜像输出目录、内容寻址缓存、日志和诊断包。

### 3.2 范围内数据

- 来源 URL、页面标题、Origin 和资源元数据。
- 网络请求与响应的安全子集。
- HTML、CSS、JavaScript、JSON、图片、字体、音频、视频、Worker、WASM、GLB、DDS、BIN 等资源体。
- `mirror.json`、`validation.json`、截图、HTML 报告和 ZIP。
- 任务状态、性能指标、错误码和本地日志。

### 3.3 明确非目标

- 绕过登录、验证码、付费墙、DRM、访问控制或反爬机制。
- 复制支付、订单、数据库或服务端业务。
- 防御已经获得当前 Windows 用户权限或管理员权限的本机恶意软件。
- 证明来源网站不存在恶意代码或版权风险。
- 保证任意第三方浏览器、GPU 驱动或解析库没有未知漏洞。
- 阻止用户在导出后主动修改、运行或重新发布镜像。
- Beta 阶段支持内网站点、`localhost`、`file:` 页面或会话凭据导出。

同一 Windows 用户下的恶意进程可以读取该用户可访问的文件和进程数据，这超出 WebMirror 的主要隔离边界。本文档中的访问令牌和 ACL 主要防御来源页面、普通网页和低权限跨 Origin 攻击，不替代主机端点安全。

## 4. 系统与数据流

```text
用户点击扩展
    |
    v
[扩展可信 UI / Service Worker]
    |
    | CDP 事件、响应元数据
    v
[不可信来源标签页、iframe、Worker、Service Worker]
    |
    | 经过过滤和 Schema 化的控制消息、资源证据
    v
[Native Messaging 边界]
    |
    v
[Local Helper 控制面]
    |             \
    |              \ 受策略约束的公开网络请求
    |               v
    |             [不可信网络与资源服务器]
    |
    +--> [任务临时目录 / 内容缓存 / 镜像目录]
    |
    +--> [只读 Preview Server] --> [不可信本地镜像页面]
    |
    +--> [隔离 Playwright Context]
    |
    +--> [报告 / ZIP / 诊断包]

[安装器 / 更新器] --> [Local Helper、Native Host Manifest、注册表]
```

### 4.1 信任边界

| 边界  | 两侧                        | 主要风险                                            | 必要控制                                                 |
| ----- | --------------------------- | --------------------------------------------------- | -------------------------------------------------------- |
| TB-01 | 来源页面 -> 扩展            | 页面数据注入、资源洪泛、导航混淆、敏感数据诱捕      | 固定 CDP 操作、输入限制、来源绑定、过滤后再持久化        |
| TB-02 | 扩展 -> Native Host         | 畸形消息、越权操作、跨任务重放、版本混淆            | 严格 Schema、消息上限、能力令牌、状态机、版本协商        |
| TB-03 | Helper -> 公网              | SSRF、DNS Rebinding、危险重定向、恶意内容           | 每跳 URL/IP 校验、连接地址固定、大小和时间限制           |
| TB-04 | Helper -> 文件系统          | 路径穿越、重解析点逃逸、任意覆盖、缓存污染          | 安全路径映射、根目录约束、原子写、Hash 校验              |
| TB-05 | 不可信预览 -> Helper 控制面 | CSRF、CORS 绕过、本地端口探测、任务控制             | 不同 Origin/端口、无 Cookie、强令牌、无 CORS、只读预览   |
| TB-06 | 不可信预览 -> 浏览器/网络   | 表单提交、数据外传、权限 API、Service Worker 持久化 | CSP、Permissions-Policy、任务唯一 Origin、隔离验证上下文 |
| TB-07 | 不可信元数据 -> 报告/UI     | HTML 注入、脚本执行、日志伪造                       | 文本编码、模板自动转义、报告 CSP、结构化日志             |
| TB-08 | 构建/更新 -> 用户设备       | 供应链替换、降级、安装提权、注册劫持                | 代码签名、Hash/SBOM、最小权限、原子更新、回滚校验        |

## 5. 资产与安全目标

| 资产                                       | 安全目标                                                     |
| ------------------------------------------ | ------------------------------------------------------------ |
| Cookie、Authorization、Token、密码、表单值 | 不采集、不持久化、不上传、不进入诊断                         |
| 本机文件和用户目录                         | 镜像页面和来源 URL 不能读取、覆盖或枚举任意文件              |
| 本机与私有网络                             | Helper 不能被页面用作 SSRF、端口扫描或云元数据访问工具       |
| Native Host 控制能力                       | 只有已授权扩展实例能发起有限、版本化的任务操作               |
| 任务与缓存完整性                           | 资源内容、Hash、路径和状态不可被跨任务混淆或静默污染         |
| 预览隔离                                   | 不可信镜像只能读取本任务资源，不能控制 Helper 或访问其他任务 |
| 安装与更新完整性                           | 只执行受信任发布者签名且版本兼容的构建                       |
| 用户隐私元数据                             | URL、标题、本地路径和使用记录仅本地最小化保存                |
| 可用性                                     | 恶意页面不能无限消耗内存、磁盘、CPU、进程、端口和网络        |
| 结果真实性                                 | 安全失败、缺失或外部依赖时不得错误标记为 `COMPLETE`          |

## 6. 攻击者模型与假设

### 6.1 攻击者

- **恶意网站作者**：完全控制来源 HTML、脚本、Worker、响应 Header、URL、重定向、文件名和资源体。
- **被入侵的第三方 CDN**：可返回与原资源类型不一致的恶意或超大内容。
- **网络攻击者**：可造成 DNS 变化、重定向、连接中断、内容截断或降级。
- **普通外部网页**：可以尝试访问用户的 `127.0.0.1` 端口、构造 CSRF、DNS Rebinding 或探测本地服务。
- **同一镜像中的恶意脚本**：在本地预览 Origin 内运行，能够发送浏览器网络请求并尝试调用权限 API。
- **恶意或被污染的依赖/更新源**：尝试替换 Helper、安装器或依赖包。
- **误操作用户**：选择系统目录作为输出、打开恶意二进制、分发包含敏感内容的 ZIP。

### 6.2 安全假设

- Chrome/Edge 和 Windows 的安全更新处于支持状态。
- WebMirror 发布签名私钥未泄漏，并与开发工作区隔离。
- 扩展只允许固定的、由项目控制的 Native Host。
- Helper 以普通用户权限运行，不安装内核驱动或常驻高权限服务。
- 用户点击是启动抓取的必要条件，但不是对页面内容可信度的证明。
- 来源页面的法律授权由用户负责；产品仍必须执行技术安全限制。

## 7. 风险分级方法

### 7.1 评分

影响和发生可能性分别按 1 至 5 评分，风险分数为：

```text
Risk Score = Impact x Likelihood
```

|  分数 | 风险级别 | 项目缺陷映射 | 处理要求                             |
| ----: | -------- | ------------ | ------------------------------------ |
| 20-25 | Critical | P0           | 立即停止分发，修复后全量回归         |
| 12-19 | High     | P0/P1        | 不得进入 Beta                        |
|  6-11 | Medium   | P1/P2        | 必须缓解；残余风险需书面接受和到期日 |
|   1-5 | Low      | P2/P3        | 进入常规修复队列并持续监控           |

影响达到 5 的典型事件包括：凭据泄漏、任意代码执行、任意文件读写、私网访问、供应链替换或广泛数据破坏。即使计算分数不足 20，也可由安全负责人直接提升为发布阻断项。

### 7.2 风险处置

- **关闭**：自动化测试证明攻击路径被阻断。
- **缓解**：降低影响或发生概率，但仍存在残余风险。
- **接受**：仅允许 Medium/Low，由人类开发者记录原因、范围、到期日和监控方式。
- **转移**：依赖浏览器、操作系统或商店安全机制时，仍需保留本地校验。
- **避免**：删除高风险能力，例如 Beta 不支持认证凭据或私网抓取。

## 8. 不可破坏的安全不变量

以下条件必须由代码结构和自动化测试保证，不允许只依赖 UI 提示：

1. 未经用户点击，不 attach 标签页、不启动抓取、不连接页面数据到 Helper。
2. 来源页面不能直接调用 Native Messaging，不能构造 Helper 命令。
3. Helper 不接受任意 URL、任意文件路径、任意可执行文件或任意命令参数。
4. 所有网络连接在 DNS 解析后和每次重定向后重新执行地址策略。
5. 所有文件读写的最终真实路径必须位于已批准任务根目录或缓存根目录内。
6. Cookie、Authorization、Proxy-Authorization、Token、密码和用户表单值不得写入磁盘。
7. 预览服务器只提供本任务只读资源，控制操作不与预览共享 Origin、Cookie 或 URL Token。
8. 不可信镜像代码不得在扩展 Origin 或 Helper 进程中执行。
9. 安全校验失败的任务不能进入 `READY`、`COMPLETE`，也不能自动导出 ZIP。
10. 未签名、签名错误、来源不明或协议不兼容的 Helper/更新必须 fail closed。

## 9. 详细威胁与控制

### 9.1 来源页面不可信

#### 威胁

- 页面标题、URL、DOM 文本或 Header 向 Popup、结果页、日志和报告注入 HTML/JavaScript。
- 页面通过 CDP 事件构造超深对象、异常编码、重复字段或极大元数据。
- 页面在抓取过程中导航到其他 Origin、打开新标签页、创建大量 iframe/Worker，扩大抓取范围。
- 页面诱导扩展执行由页面拼接的 `Runtime.evaluate` 表达式。
- 页面发起 POST、PUT、DELETE、Beacon、WebSocket 或表单请求，诱导 Helper 重放写操作。
- 页面加载本机、私网、云元数据或已登录第三方站点资源，再利用 CDP 响应体能力间接导出。
- 页面制造无限请求、重定向、DOM、Blob、Worker 或压缩资源导致拒绝服务。
- Service Worker CacheStorage 包含过期、跨范围或凭据绑定内容。
- 页面利用本地预览被浏览器视为可信 `localhost` 环境，调用敏感浏览器 API。

#### 控制

1. 抓取会话绑定启动时的 `tabId`、主 Frame 和最终主文档 Origin。主 Frame 后续跨 Origin 导航必须暂停并要求重新确认；新标签页默认不加入任务。
2. 只允许固定、代码内定义的 CDP 命令和表达式。禁止把页面字符串拼接到 `Runtime.evaluate`、脚本源或选择器代码中。
3. 页面元数据进入 UI 时使用 `textContent` 或框架自动转义；禁止使用 `innerHTML`。报告模板对 URL、标题、错误、Header 和文件名统一 HTML 编码。
4. 来源网络事件先转换为内部类型，再进入 Native Messaging。原始 CDP 对象不得直接透传。
5. Helper 只下载经扩展观察并生成资源证据的 `GET`/`HEAD` 静态资源。POST、PUT、PATCH、DELETE、Beacon、WebSocket 和 EventSource 不重放，仅记录脱敏类别。
6. 即使浏览器已经观察到请求，也必须拒绝本机、私网、保留地址和带凭据资源。CDP “已观察到”不能绕过 SSRF 和隐私策略。
7. Beta 安全硬上限建议为：每任务 2,000 个资源、解码后 250 MiB、单资源 50 MiB、单控制消息 256 KiB。超过后停止新增资源并标记 `PARTIAL` 或 `FAILED`，不得崩溃或错误 `COMPLETE`。
8. iframe、Worker、Service Worker 和 CacheStorage 资源使用同一 URL、凭据和地址策略。CacheStorage 只读，不复制 Cookie、请求 Header 或不符合策略的响应。
9. 扩展内容脚本不得向页面暴露 Native Host 代理，不监听页面可伪造的 `window.postMessage` 控制命令。
10. 扩展从页面读取数据时使用隔离世界；抓取代码和页面代码之间只传最小、可验证的纯数据。

### 9.2 Native Messaging

#### 威胁

- 畸形 JSON、超大消息、深层嵌套或消息洪泛导致 Host 崩溃或耗尽内存。
- 未知消息类型、额外字段、原型污染键或数值溢出绕过业务校验。
- 旧扩展与新 Helper 协议不兼容，造成参数含义混淆。
- 页面或被攻陷的扩展逻辑传入任意下载 URL、输出路径、命令、可执行文件或 Shell 参数。
- 跨任务重放、伪造 `taskId`、重复取消/完成消息破坏状态机。
- Host 将日志写到 stdout，破坏 Native Messaging 帧或泄漏数据。
- Native Host Manifest 允许非预期扩展 ID。

#### 控制

1. 协议消息固定包含 `protocolVersion`、`messageType`、`requestId`、`taskId` 和受 Schema 约束的 `payload`。
2. 使用严格 JSON Schema：`additionalProperties: false`、字符串长度上限、数组数量上限、整数范围、枚举消息类型，并显式拒绝 `__proto__`、`prototype`、`constructor` 等危险键。
3. 在解析完整消息前执行字节长度限制；控制消息默认不超过 256 KiB，资源列表采用小批次分页，不传输大资源体。
4. 协议握手先协商版本和能力；不兼容时拒绝创建任务，不尝试猜测兼容。
5. Helper 是任务 ID、任务能力令牌和状态机的最终权威。扩展不能自行把任务置为 `READY` 或 `COMPLETE`。
6. 每个状态变更校验当前状态、调用能力和幂等键；过期、跨任务或重复消息返回稳定错误，不产生副作用。
7. 协议不提供通用 `exec`、`spawn`、`readFile`、`writeFile`、`downloadUrl` 或任意路径接口。所有操作使用有限命令和 Helper 生成的资源 ID。
8. 启动子进程时使用固定可执行文件和参数数组，禁止 `shell: true`，禁止把来源页面字符串作为命令行。
9. Native Host stdout 仅用于协议帧；日志写 stderr 或受控日志文件，且先脱敏。
10. Native Host Manifest 的 `allowed_origins` 仅包含正式 Chrome/Edge 扩展 ID；Manifest、可执行文件和注册表项使用当前用户最小 ACL。
11. 对消息速率、未完成请求数和握手超时设限。连接断开后终止未授权操作，任务进入可诊断的失败或中断状态。

### 9.3 SSRF、危险 URL 与重定向

#### 威胁

- 页面要求 Helper 请求 `127.0.0.1`、局域网、VPN、路由器、数据库、Windows 服务或云元数据地址。
- 使用十进制/八进制/十六进制 IPv4、IPv4-mapped IPv6、Unicode 主机名、尾点、userinfo 或混合编码绕过字符串黑名单。
- 公网域名先解析到公网地址，随后 DNS Rebinding 到私网。
- 公网 URL 重定向到 `file:`、本机、私网、凭据 URL 或无限重定向链。
- Helper 自动继承 `HTTP_PROXY`、`HTTPS_PROXY` 或系统代理，绕过直接地址检查。
- HTTPS 资源被降级到 HTTP，或连接地址与已校验 DNS 地址不一致。
- 页面仅通过 Native Messaging 构造一个“已观察资源”记录，诱导 Helper 请求任意 URL。

#### URL 决策流程

每一个初始 URL 和每一次重定向都必须依次执行：

1. 使用单一标准 URL Parser 解析一次，拒绝二次解码后语义变化的输入。
2. 仅允许 `http:` 和 `https:`。`data:`、`blob:` 只能作为浏览器已捕获的内联数据处理，Helper 不主动请求。拒绝 `file:`、`ftp:`、`gopher:`、`ws:`、`wss:`、`chrome:`、`chrome-extension:`、`edge:`、`devtools:` 和自定义协议。
3. 拒绝包含 username/password 的 URL；移除 Fragment；限制主机名、路径和查询长度。
4. 验证 URL 对应当前任务的不可伪造资源证据，且方法为 `GET` 或 `HEAD`。
5. 对 IDNA 主机名规范化，并解析全部 A/AAAA 记录。只要任一候选地址属于禁止范围，默认拒绝该主机。
6. 禁止回环、私网、链路本地、共享地址、组播、广播、保留、未指定地址和 IPv4-mapped IPv6 等等价形式。至少覆盖：
   - IPv4：`0.0.0.0/8`、`10.0.0.0/8`、`100.64.0.0/10`、`127.0.0.0/8`、`169.254.0.0/16`、`172.16.0.0/12`、`192.0.0.0/24`、`192.0.2.0/24`、`192.168.0.0/16`、`198.18.0.0/15`、`198.51.100.0/24`、`203.0.113.0/24`、`224.0.0.0/4`、`240.0.0.0/4`。
   - IPv6：`::/128`、`::1/128`、`fc00::/7`、`fe80::/10`、`ff00::/8`、文档和保留范围，以及映射到被拒绝 IPv4 的地址。
7. 将通过校验的解析结果固定到实际连接，连接建立时核对远端 IP，避免校验后重新解析到其他地址。
8. 默认不继承环境变量或系统代理。未来支持代理时，代理本身必须受显式配置、地址策略和单独威胁评审约束。
9. 最多跟随 5 次重定向。每一跳重新执行完整策略；拒绝 HTTPS 到 HTTP 降级、危险协议、userinfo、私网目标和重定向循环。
10. 在读取响应体前检查状态、Header 大小、`Content-Length` 和解码预算；流式读取时持续执行字节上限。

Beta 默认不支持本机、内网或 VPN 页面。即使用户已授权内网站点，也必须通过后续独立的企业模式、显式策略和新安全评审实现，不得通过隐藏设置关闭上述检查。

### 9.4 路径穿越、任意文件读写与缓存

#### 威胁

- URL 路径中的 `../`、反斜杠、双重编码、绝对路径、UNC、驱动器名或 NT 设备路径逃出任务目录。
- Windows 保留名、尾随点/空格、Alternate Data Stream（如 `file.txt:payload`）造成路径解释差异。
- 大小写、Unicode 规范化和截断导致两个 URL 映射到同一文件。
- 攻击者预先创建符号链接、Junction 或其他 Reparse Point，使检查后的写入落到目录外。
- 预览请求使用编码差异读取任务目录外文件。
- 内容缓存使用可写 Hard Link，用户修改镜像时污染全局缓存。
- 下载中断留下被误认为完整的文件。

#### 控制

1. 原始 URL 不直接拼接文件系统路径。URL 先映射到内部资源 ID，再由安全段编码器生成可读但受控的相对路径；冲突时附加内容或 URL Hash。
2. 路径段拒绝空段、`.`、`..`、控制字符、NUL、冒号、驱动器前缀、UNC/NT 前缀、尾随点/空格和 Windows 保留名。正斜杠、反斜杠和编码后的分隔符统一处理。
3. 对 Unicode 使用固定规范化形式；在 Windows 大小写不敏感语义下检测冲突。任何规范化后的重复路径必须生成不同的 Hash 后缀。
4. 每次读写前计算绝对路径，并验证其位于批准根目录内。字符串前缀比较不足以作为根目录校验，必须按路径段和大小写规则判断。
5. 任务根目录由 Helper 创建并持有，不从页面或 Native 消息接收任意绝对路径。用户选择的输出根只在可信 UI 流程中设置，并拒绝 Windows、Program Files、浏览器配置、仓库和其他高风险系统目录。
6. 创建和写入前检查现有父目录不存在 Reparse Point。关键写入使用不跟随链接的文件打开策略；不支持可靠 no-follow 的路径必须采用受控新目录、最小 ACL 和写前/写后真实路径复核。
7. 下载写入同目录随机临时文件，完成大小和 SHA-256 校验后原子改名。临时文件永不进入 `COMPLETE` 清单。
8. 内容寻址缓存对象不可变。复用前重新验证 Hash；镜像不得通过可写 Hard Link 指向缓存对象，使用复制、只读链接或受保护的只读对象。
9. Preview Server 使用同一安全路径解析器，禁止目录列表，拒绝未知任务、绝对路径、编码穿越和范围外文件。
10. 任务取消、磁盘不足或 Helper 崩溃时将目录标记为中断，不能作为成功结果打开或导出。

### 9.5 Zip Slip 与导出

MVP 只创建 ZIP，不导入或解压第三方 ZIP。任何未来的镜像导入功能都需要新的威胁模型和独立解压沙箱。

导出要求：

1. ZIP Entry 只来自已经通过路径校验的任务清单，不直接使用来源 URL 或 Header 文件名。
2. Entry 使用 `/` 作为分隔符，必须是非空相对路径，拒绝 `..`、绝对路径、驱动器、UNC、NUL、控制字符、ADS、尾随点/空格和设备名。
3. 禁止在 ZIP 中创建符号链接、Junction、Hard Link 或设备文件条目。
4. 检测大小写、Unicode、规范化和截断后的重复 Entry；冲突时安全重命名并更新清单。
5. ZIP 输出文件本身只能写入用户批准的导出目录，使用临时文件加原子改名。
6. 导出完成后使用独立 ZIP Reader 枚举全部 Entry 并重复校验。测试中必须解压到临时沙箱并证明沙箱外哨兵文件未变化。
7. 来源网站提供的 ZIP、7z、RAR 等归档资源按普通不透明字节保存，不自动展开。

### 9.6 本地预览与控制 API 隔离

#### 安全模型

本地镜像页面仍是来源网站的不可信代码。`127.0.0.1`、随机端口和 CORS 单独都不是充分安全边界，因为普通网页可以向本地端口发送请求，且不需要读取响应即可触发 CSRF。

#### Preview Plane

- 只绑定 `127.0.0.1`，不绑定 `0.0.0.0`、LAN、IPv6 Any 或公网接口。
- 每个任务使用不可复用的随机任务 ID 和独立 Origin。推荐形式为随机子域加随机端口，例如 `<128-bit-id>.webmirror.localhost:<port>`，并严格校验 `Host` Header。
- 端口随机化只用于降低偶然冲突，不作为认证机制。
- 只允许 `GET` 和 `HEAD`；拒绝上传、写入、删除、命令、目录列表和状态变更。
- 单个 Preview Origin 只能映射一个任务根目录，不能通过路径或查询参数切换任务。
- 不在响应、HTML、URL、Cookie、LocalStorage 或页面可读脚本中放置控制 Token。
- 使用 `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer` 和按兼容性生成的安全 Header。
- 默认安全预览策略禁止远程连接和表单提交。基线 CSP 至少约束：
  - `connect-src` 仅允许本任务 Origin、必要的 `data:`/`blob:`。
  - `form-action 'none'`。
  - `object-src 'none'`。
  - `base-uri 'self'`。
  - 脚本、样式、字体、图片、媒体、Worker 和 Frame 只允许已本地化来源。
- 通过 `Permissions-Policy` 默认禁用摄像头、麦克风、地理位置、支付、USB、Serial、HID、Bluetooth、MIDI 和剪贴板读取等敏感能力。
- 打开预览时使用 `noopener`，不让镜像获得可信结果页的 `window.opener`。

为兼容部分 WebGL 页面，CSP 可能需要允许本地 `unsafe-inline`、`unsafe-eval` 或 `blob:` Worker。允许这些能力不代表信任页面代码，因此必须同时保持 `connect-src`、`form-action`、控制面和任务 Origin 隔离。任何“兼容模式”不得默认放开远程网络或控制接口。

#### Control Plane

首选方案是仅通过 Native Messaging 执行任务控制，不向浏览器页面暴露 HTTP 控制 API。若验证器或桌面组件必须使用本地 HTTP 控制面，则必须满足：

1. 使用独立端口或命名管道，与 Preview Origin 完全分离。
2. 使用至少 256 bit CSPRNG 生成的会话能力令牌，通过自定义 Header 传输；禁止放在 URL、Cookie、HTML、日志或 Referrer 中。
3. 不返回 `Access-Control-Allow-Origin: *`，不支持凭据 CORS。仅允许明确的扩展 Origin 或本地受信客户端。
4. 状态变更只接受带正确 Content-Type、Token、任务能力和幂等键的 POST；GET/HEAD 无副作用。
5. 拒绝浏览器 simple request、无 Origin 的异常浏览器请求、未知 Host、预检绕过和跨任务 Token。
6. 每个 Token 绑定进程会话、调用方、任务和允许操作，短期有效，任务结束立即失效。
7. 记录脱敏安全事件并限速；连续认证失败不能导致 Helper 崩溃。

#### Service Worker 与验证器

- 每个任务使用唯一 Origin，任务 ID 永不复用，避免旧 Service Worker 控制后续任务。
- 任务关闭后尽力注销 Service Worker、清理 CacheStorage 和验证用户数据目录。
- Playwright 使用全新临时 Context，不加载用户浏览器 Profile、Cookie、密码、扩展或客户端证书。
- Chromium Sandbox 必须开启，禁止使用 `--no-sandbox`。
- 验证任务有总超时、CPU/内存上限和进程树终止策略；恶意无限循环不能永久占用资源。
- `COMPLETE` 验证必须证明没有非本地请求。发现远程请求时进入 `PARTIAL` 或 `FAILED`。

### 9.7 Cookie、Token、表单和浏览器数据

#### 数据分类

| 分类          | 示例                                                                           | 默认处理                     |
| ------------- | ------------------------------------------------------------------------------ | ---------------------------- |
| D0 禁止持久化 | Cookie、Authorization、密码、OAuth/JWT、Session ID、私钥、CSRF Token、用户输入 | 采集边界立即丢弃             |
| D1 敏感内容   | 页面正文、截图、响应体、用户可见个人数据                                       | 仅本地任务目录，明确用户触发 |
| D2 私密元数据 | 完整 URL、标题、Origin、本地路径、错误详情                                     | 最小化、脱敏、限期保存       |
| D3 运行指标   | 阶段耗时、资源数、错误码、版本                                                 | 默认本地；遥测需另行同意     |

#### 控制

1. 请求 Header 采用允许列表，而不是仅用敏感字段黑名单。允许持久化的典型字段仅限 `Content-Type`、`Content-Length`、`ETag`、`Last-Modified`、安全的缓存和 Range 元数据。
2. `Cookie`、`Set-Cookie`、`Authorization`、`Proxy-Authorization`、客户端证书信息和常见自定义 Token Header 在进入任务模型、日志和 Native Messaging 前删除。
3. 原始签名 URL 仅在单次内存下载流程中短暂存在，不写入日志、清单、缓存索引、报告或诊断包。持久化 URL 删除敏感查询值，并保存不可逆 Fingerprint 供关联。
4. `mirror.json` 中的“原 URL”解释为可追踪的脱敏 URL，不得违反 FR-014。资源本地映射使用内部资源 ID，不依赖持久化原始 Token。
5. 不读取或导出 LocalStorage、SessionStorage、IndexedDB、浏览器密码、浏览历史、Cookie Store 或扩展存储中的页面凭据。
6. 不序列化实时表单状态。所有 `input`、`textarea`、`select` 和 contenteditable 的用户值在 DOM 兜底快照中清空；密码和隐藏 Token 字段一律清空。
7. 不重放带凭据的资源请求。Beta 优先对公开资源执行无 Cookie、无 Authorization 的重新获取；只有无需凭据仍可获得的资源才能进入普通镜像。
8. 需要会话才能获得的资源标记为不支持或安全失败，不把浏览器 Cookie 写入 Helper。未来认证内容模式必须单独设计加密、保留期、用户确认和导出限制。
9. 对 HTML、JSON、JavaScript、Source Map 和配置文件执行高置信度 Secret Scan。检测到私钥、Bearer/JWT、云密钥或会话凭据时阻止 `COMPLETE` 和 ZIP，返回安全错误并隔离任务。
10. 截图和页面正文可能天然包含用户可见敏感信息。产品必须在开始前提示输出包含页面内容，并将目录 ACL 限制为当前用户；诊断包默认不包含截图和正文。
11. 默认不上传任何页面内容、URL、截图、日志或任务数据。未来遥测必须独立 Opt-in，并继续禁止 D0/D1 数据。

### 9.8 日志与诊断脱敏

1. 使用结构化 JSON 日志和固定字段允许列表，不记录原始 Native 消息、请求/响应 Header、响应体、DOM、完整查询字符串或页面脚本。
2. URL 日志默认仅保留 scheme、注册域、脱敏路径摘要和查询键数量；查询值全部删除或 HMAC 化。
3. 本地文件路径只记录任务相对路径或路径 Hash，不记录用户名、Home 目录和任意来源文件名。
4. 对 Bearer、JWT、OAuth、AWS/GCP/Azure 密钥、Cookie、签名查询、邮箱和高熵字符串执行统一脱敏。脱敏函数位于共享模块，UI、Helper、报告和诊断不能各自实现。
5. 转义 CR、LF、TAB、ANSI 控制序列和双向文本控制字符，防止日志伪造和终端欺骗。
6. 字段长度和事件频率有上限；重复错误聚合计数，避免恶意页面填满磁盘。
7. Native Host 不在 stdout 输出日志。崩溃处理不得把环境变量、命令行、内存转储或原始页面数据自动上传。
8. 诊断包由用户主动生成，采用明确允许列表；生成后运行 Secret Scan 并展示将包含的文件类型。
9. 建议 Beta 默认日志保留 14 天、中断临时目录保留不超过 24 小时。缓存和镜像由用户控制清理，但 UI 必须提供按任务和全部删除。

### 9.9 恶意资源、解析器与本地执行

#### 威胁

- 解压炸弹、异常 Content-Encoding、巨型 Header、慢响应和无限流。
- 深层 JSON、CSS、HTML、Source Map、WASM、GLB 或 AST 输入触发解析器 DoS 或漏洞。
- MIME 与内容不符、Polyglot 文件、可执行文件或脚本伪装成图片。
- Helper 误用 `eval`、动态 `import`、`require`、Shell 或系统文件关联执行下载内容。
- 报告生成器把不可信错误、标题或 URL 当作 HTML。
- 恶意脚本在 Playwright 验证中无限循环、创建进程或消耗 GPU。
- 损坏或被替换的缓存对象传播到多个任务。

#### 控制

1. 抓取关键路径将二进制资源视为不透明字节。只有确有必要的文本/清单类型进入解析器。
2. 同时限制压缩后字节、解码后字节、压缩比、Header 大小、读取时间、空闲超时和任务总预算。达到上限立即中止该资源。
3. 大型或复杂解析器在受限 Worker/子进程中运行，设置内存、CPU、递归深度和超时；解析失败只影响该资源。
4. 不信任扩展名和远端 MIME。使用安全 MIME 映射和必要的内容签名检测；本地服务默认 `nosniff`。
5. Helper 绝不执行、加载或反序列化为代码的来源 JavaScript、WASM、DLL、EXE、脚本或归档。禁止动态 `require/import` 镜像路径、`eval` 和 Shell 打开。
6. 用户点击“打开镜像”只能打开受控 HTTP 入口，不能自动调用来源资源的 Windows 文件关联。
7. HTML 报告使用自动转义模板和严格 CSP；不可信值只作为文本或 JSON 编码数据。
8. Playwright 运行在浏览器 Sandbox 和临时 Profile 中，设置导航、动作、页面、Context 和总进程超时。超时后终止整个验证进程树。
9. CAS 对象以 SHA-256 命名，写入和复用时验证 Hash。Hash 或长度不匹配时隔离并重新下载，不能静默使用。
10. 可选调用 Windows Defender 或企业杀毒作为附加信号，但不能把杀毒扫描作为唯一安全边界。
11. 源站归档、磁盘镜像和安装包资源不自动解压或执行。

### 9.10 安装、注册与更新

#### 安装

- Helper 和安装器必须使用受信任发布证书进行 Authenticode 签名；扩展通过 Chrome Web Store/Edge Add-ons 或受控开发通道分发。
- 默认按当前用户安装，不创建高权限 Windows 服务，不要求管理员权限，除非存在经过 ADR 和安全评审的必要性。
- Native Host Manifest 使用绝对路径、固定 Host 名和正式扩展 ID 允许列表。注册表键、Manifest 目录和可执行文件 ACL 不允许普通网页或低权限跨用户修改。
- 安装器不修改全局 `PATH`，不从当前工作目录加载 DLL，不执行来源页面提供的参数。
- 开发、Canary、Beta、Stable 使用不同标识、签名或明确通道，避免测试构建覆盖正式 Host。

#### 更新

1. 扩展和 Helper 独立版本化，Native 协议单独版本化；连接前必须完成兼容协商。
2. Helper 更新包通过 TLS 获取，并再次验证发布签名、产品 ID、目标架构、版本和 SHA-256。TLS 不能替代代码签名。
3. 拒绝未签名、签名链无效、签名主体不匹配、Hash 不符和默认降级更新。紧急回滚只能安装预先签名且在允许回滚清单中的版本。
4. 更新先写入临时位置，完整验证后原子切换；中断时保留上一可运行版本。
5. 更新器不接受页面或 Native 消息提供的任意 URL、文件路径或命令行。
6. 构建锁定依赖版本，生成 SBOM、构建 Hash 和来源记录；CI 执行依赖漏洞、恶意包、许可证和 Secret Scan。
7. 发布签名密钥不进入仓库、日志或普通 CI Artifact；签名操作需要人工批准。
8. 卸载默认不删除用户镜像；删除缓存和日志需明确选择。卸载必须移除 Native Host 注册、自动启动项和更新任务。

### 9.11 可用性、滥用和结果欺骗

- 资源数、总字节、单资源、重定向、并发、解析时间、验证时间、日志大小、任务数和磁盘占用都必须有硬限制。
- 用户取消后停止新网络请求和验证进程；中断目录不能显示为成功。
- Helper 崩溃、Native Messaging 断线、磁盘不足、Hash 不一致、安全策略拒绝或远程请求残留时，不得产生 `COMPLETE`。
- 本地预览默认禁用表单提交和远程写接口，减少离线镜像被用于收集凭据的能力。
- 结果页和报告明确显示“本地镜像”、来源、抓取时间和外部依赖，避免用户把本地副本误认为原站。
- 产品不能完全阻止用户导出后移除限制并重新发布。该残余滥用风险通过授权声明、使用条款、默认安全预览和不提供后端/登录复制能力降低。

## 12. Beta 安全门

- 本文档经过一次独立上下文的安全审查和人类开发者确认。
- 风险登记表中 Critical/High 残余风险为 0。
- P0/P1 安全缺陷为 0。
- 每个 Medium 残余风险有负责人、接受理由、影响范围、监控方式和到期复审日期。
- 所有安全相关 ADR 已完成，代码行为与 ADR/本文档一致。

### 12.2 自动化证据

- `tests/security` 全量通过，失败重试不能作为通过依据。
- SSRF 哨兵对所有禁止地址、重定向和 Rebinding 测试的连接数均为 0。
- 路径穿越、Reparse Point 和 ZIP 测试证明任务根目录外哨兵无变化。
- 恶意 Preview 无法调用 Control API、访问其他任务或读取任意本机文件。
- Canary Secret 在任务目录、缓存、临时目录、日志、报告、ZIP、诊断包和崩溃路径中的命中数为 0。
- `COMPLETE` 结果远程请求为 0，本地资源 404 为 0。
- 超额资源、解析器超时、Helper 崩溃和断线均不会产生错误 `COMPLETE`。

### 12.3 安装与供应链

- 扩展包只包含声明的权限和文件，Native Host 只允许正式扩展 ID。

- 无已知可利用的 Critical/High 依赖漏洞；例外必须有不可达证明和短期修复期限。
- 发布签名密钥未出现在仓库、CI 日志或 Artifact 中。

### 12.4 浏览器与运行环境

- Chrome 和 Edge 当前稳定版核心安全 E2E 通过。
- Playwright/Chromium Sandbox 未被关闭。
- Preview/Control 仅监听 Loopback，LAN 访问测试失败。

### 12.5 一票否决

出现以下任一情况立即 No-Go：

- 任意凭据或用户表单值持久化。
- 任意禁止地址收到 Helper 请求。
- 任意任务根目录外读写。
- 预览页面可以改变 Helper 状态。
- 安全失败被标记为 `COMPLETE`。
- 未签名或签名校验失败的软件被安装/更新。
- 未关闭的 Critical/High 风险或 P0/P1 安全缺陷。

不得通过“仅文档提示”“仅 Beta 用户”“概率很低”或关闭测试来豁免一票否决项。

## 13. 安全事件与响应

1. 发现凭据泄漏、任意文件访问、SSRF、RCE 或更新替换时，立即停止对应版本分发和自动更新。
2. 保存最小脱敏复现、受影响版本、攻击前提和可观察证据，不复制真实用户 Secret 到缺陷系统。
3. 判断是否需要吊销发布证书、停止商店发布、撤回安装包或强制升级。
4. 修复必须增加永久自动化 Fixture，并运行全部安全、离线和核心 E2E。
5. 对可能已经生成的敏感缓存、日志和诊断包提供检测与删除工具。
6. 发布安全公告时说明影响版本、条件、修复版本和用户操作，不披露用户页面内容。
7. 事件关闭后更新本文档、风险登记表、ADR、测试矩阵和发布清单。

## 16. 已知残余风险

即使全部控制生效，仍存在以下不能完全消除的风险：

- 响应正文和截图可能包含用户可见但 Secret Scanner 无法语义识别的个人信息。
- 浏览器、GPU 驱动、媒体解码器和第三方 Parser 可能存在未知漏洞。
- 同一 Windows 用户下的恶意本机进程可能读取输出或进程内存。
- 为 WebGL 兼容允许本地 `unsafe-eval`、内联脚本或 Blob Worker 时，镜像代码仍能在自身隔离 Origin 内完整执行。
- 用户可在导出后主动移除安全限制、恢复远程接口或重新发布镜像。
- 独立验证无法证明所有交互状态都不产生远程请求，只能覆盖已执行状态和静态分析结果。

这些残余风险不能通过把页面称为“静态网站”而忽略。公开 Beta 前，人类开发者必须明确接受仍为 Medium 的风险，并确保产品文案不承诺绝对安全、绝对完整或任意认证网站复制。
